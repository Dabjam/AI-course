# HW07 — Отчёт по кластеризации

## 1. Datasets

Вы выбрали 3 датасета: `S07-hw-dataset-01.csv`, `S07-hw-dataset-02.csv`, `S07-hw-dataset-03.csv`.

### 1.1 Dataset A

- Файл: `S07-hw-dataset-01.csv`
- Размер: 12000 строк, 8 признаков
- Признаки: все числовые
- Пропуски: отсутствуют (обработаны/проверены в препроцессинге)
- "Подлости" датасета: признаки в разных шкалах, есть шумовые признаки, возможна разношкалность и выбросы

### 1.2 Dataset B

- Файл: `S07-hw-dataset-02.csv`
- Размер: 8000 строк, 3 признака
- Признаки: числовые
- Пропуски: отсутствуют (обработаны/проверены)
- "Подлости" датасета: нелинейная структура кластеров, выбросы и отдельный шумовой признак

### 1.3 Dataset C

- Файл: `S07-hw-dataset-03.csv`
- Размер: 15000 строк, 4 признака
- Признаки: числовые
- Пропуски: отсутствуют (обработаны/проверены)
- "Подлости" датасета: кластеры разной плотности и фоновой шум, что усложняет подбор `eps` для DBSCAN

## 2. Protocol

- Препроцессинг: заполнение пропусков `SimpleImputer` (median для числовых), масштабирование `StandardScaler`. Для категориальных признаков использовался `OneHotEncoder(handle_unknown='ignore')`, но в текущих датасетах категорий нет. Препроцессинг оформлен через `Pipeline` + `ColumnTransformer`.
- Поиск гиперпараметров:
  - Для KMeans: перебор `k` в диапазоне 2..6 (в ноутбуке ограничение `max_k = min(7, n_samples)` применялось для защиты от слишком большого `k`).
  - Для DBSCAN (когда применялся): использовались стандартные значения примера (`eps=0.5`, `min_samples=5`) и проверялась доля шума; для Agglomerative проверялся `linkage='average'` как вариант.
  - Критерий выбора "лучшего": внутренняя метрика `silhouette_score` (основной), с дополнительной проверкой `davies_bouldin_score` (ниже — лучше) и `calinski_harabasz_score` (выше — лучше).
- Визуализация: PCA(2D) для всех датасетов (сохранены графики в `artifacts/figures/`); дополнительно строились графики "silhouette vs k".

## 3. Models

Для каждого датасета сравнивались минимум 2 метода:

- `KMeans`: подбор `k` на сетке 2..6; фиксирован `random_state=42`, `n_init=10`.
- Альтернативный метод (в зависимости от числа признаков):
  - Для Dataset A (8 признаков) использовался `DBSCAN` (eps/min_samples), так как размерность >4.
  - Для Dataset B (3 признака) использовалась `AgglomerativeClustering` (фиксированный `linkage='average'`).
  - Для Dataset C (4 признака) использовалась `AgglomerativeClustering`.

Опционально: в ноутбуке подготовлена логика для переключения между DBSCAN и иерархической кластеризацией по числу признаков.

## 4. Results

### 4.1 Dataset A

- Лучший метод и параметры: `KMeans`, `k=2` (по silhouette)
- Метрики (KMeans): silhouette=0.5216395622404242, Davies-Bouldin=0.6853295219054459, Calinski-Harabasz=11786.95462267153
- Альтернатива (DBSCAN): silhouette=0.28312477366901373, DB=0.946760657362018, CH=4301.220982297523; доля шума ≈ 0.0337
- Коротко: KMeans даёт более высокую внутреннюю согласованность для этого датасета (высокий silhouette), вероятно потому, что кластеры ближе к «сферическим» формам после масштабирования.

### 4.2 Dataset B

- Лучший метод и параметры: `KMeans`, `k=2` (по сохранённым результатам), но альтернативный метод (`AgglomerativeClustering`) показал более высокий silhouette.
- Метрики (KMeans): silhouette=0.3068610017701601, DB=1.3234721699867644, CH=3573.3933329348392
- Метрики (Agglomerative): silhouette=0.41976775922231674, DB=0.8791287795996852, CH=395.4825694831712
- Коротко: у датасета наблюдается нелинейная структура и выбросы; иерархический подход дал лучший silhouette, что указывает на то, что KMeans плохо захватывает немонотонные формы кластеров.

### 4.3 Dataset C

- Лучший метод и параметры: `KMeans`, `k=3` (по silhouette)
- Метрики (KMeans): silhouette=0.31554470037825183, DB=1.1577256320598661, CH=6957.162639510166
- Метрики (Agglomerative): silhouette=0.2556565008597179, DB=0.9650617082850917, CH=78.99058767304909
- Коротко: KMeans показал небольшое преимущество по внутренним метрикам; при этом разные плотности кластеров усложняют применение методов плотности (DBSCAN) и требуют тщательного подбора `eps`.

## 5. Analysis

### 5.1 Сравнение алгоритмов (важные наблюдения)

- KMeans хорошо работает на датасетах с относительно «сферическими» кластерами и согласованными масштабами признаков (после `StandardScaler`).
- KMeans «ломается», когда кластеры нелинейной формы или имеют сильно различающуюся плотность — тогда выигрывают иерархические методы или методы, устойчивые к форме кластеров.
- DBSCAN полезен при наличии выбросов и сложной формы кластеров, но чувствителен к подбору `eps` (особенно при переменной плотности).
- Главные факторы, влияющие на результат: масштабирование, выбросы и вариация плотности кластеров.

### 5.2 Устойчивость (обязательно для одного датасета)

- Для Dataset A была проведена проверка устойчивости KMeans: 5 запусков с разными `random_state` (в ноутбуке выполнено 5 запусков, ARI между парами результатов показал среднее значение `mean ARI = 1.0`).
- Вывод: разбиение стабильно при фиксированном выборе `k` и использованных параметрах (ARI=1.0 означает полное совпадение разбиений между запусками).

### 5.3 Интерпретация кластеров

- Кластеры интерпретировались через профили признаков (средние/медианы) и визуализацию в PCA(2D). Для Dataset A кластеры различаются по комбинациям нескольких признаков (в том числе шумовых), для Dataset B и C также видны характерные профильные отличия, что позволяет давать базовую интерпретацию.

## 6. Conclusion

- Важно правильно масштабировать признаки перед применением distance-based методов.
- KMeans удобен и быстър, но чувствителен к форме кластеров и выбросам.
- Agglomerative/DBSCAN могут выигрывать на нелинейных или шумных датасетах, но требуют аккуратного подбора гиперпараметров.
- Внутренние метрики (silhouette/DB/CH) дают разную информацию — лучше смотреть их в связке, а не полагаться только на одну метрику.
- Проверка устойчивости (несколько запусков с разными seed) помогает оценить надёжность разбиения.
